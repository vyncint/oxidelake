# Security and performance audit — 2026-09-02

Scope: the whole workspace at `5eee791` (v1 complete, ~14.4k lines of Rust plus
~740 lines of CUDA C and MSL). Method: a line-by-line read of every `unsafe`
block, every network- or input-facing surface and every hot path, one
automated performance review used as a second pair of eyes, and `cargo deny`
against the RustSec database. Every finding below was verified against the
code before it was acted on; the fixes landed in commit `b5fa34e` and are
covered by the gate (108 default tests, 49 Metal-lane tests, the on-device
conformance suite).

Severity: **high** = wrong results, hangs or unbounded resource use reachable
in normal operation; **medium** = degraded robustness or a real but bounded
cost; **low** = hygiene.

## Security and robustness findings

| ID | Sev. | Where | Finding | Status |
|---|---|---|---|---|
| S1 | high | `kernels/cuda/aggregation.cu` | The slot-claim spin-wait (`while (g_state[slot] == 1u) {}`) read a plain global; the compiler may hoist the load and turn the wait into an infinite loop → GPU hang under insert contention. | **Fixed** — volatile read; documented dependence on independent thread scheduling (sm_70+). Compile-verified only: no CUDA machine has run this code. |
| S2 | medium | `oxidelake-core/telemetry.rs`, `oxidelake-compute/exec/mod.rs` | One `OperatorStats` was registered per `execute()` call (per partition, per query) and never released → unbounded growth of a long-lived session's hub. | **Fixed** — one registration per exec instance, hub capped at 4096 entries (oldest evicted), `clear_operators()` added. |
| S3 | medium | `oxidelake-storage/datagen.rs` | `gen-data` materialised every batch before writing; `--rows` in the billions would exhaust memory. | **Fixed** — chunks stream into `ParquetFileWriter`; peak memory is one chunk + one row group. |
| S4 | medium | `oxidelake-device/metal.rs` | A new `MTLCommandQueue` per operator per partition per query; Metal caps live queues per device and `newCommandQueue` then returns nil → device errors mid-query. | **Fixed** — a pool of four queues shared by all streams. |
| S5 | low | `oxidelake-compute/exec/mod.rs` | `Predicate::And` is recursive; plan payloads arrive over the network, so a hostile tree could exhaust the stack in the evaluators. | **Fixed** — `MAX_PREDICATE_LEAVES = 64` enforced at construction (decode still recurses; a malicious scheduler is outside the trust model, see `SECURITY.md`). |
| S6 | low | `oxidelake-runtime/dashboard.rs` | Generated profiling SQL quoted column identifiers but not the table identifier from `--table NAME=PATH`. | **Fixed** — identical quoting for both. |
| S7 | info | `oxidelake-runtime` binaries | Cluster mode has no TLS/authentication (documented v1 scope); scheduler and worker bind `127.0.0.1` by default (verified in Ballista 54's `ExecutorProcessConfig::default`). | **Documented** — trust model in `SECURITY.md`. |
| S8 | info | dependencies | `quick-xml` 0.39 (RUSTSEC-2026-0194/0195, via `object_store`'s cloud backends), `paste` (unmaintained proc-macro via `arrow-flight`). `object_store` is pinned to 0.13 by DataFusion 54. | **Accepted with reasons** in `deny.toml`; cloud backends are never registered by OxideLake; revisit on the next chain bump. |
| S9 | info | `Cargo.toml` | `rust-version = "1.88"` was not true: the lockfile needs 1.94.1 (Ballista's bundled AWS SDK crates). | **Fixed** — `rust-version = "1.94.1"`, verified by `make msrv` and the `msrv` CI job. |

`unsafe` audit: every block in `oxidelake-memory` (aligned allocator, pinned CUDA
memory, Metal shared buffers), `oxidelake-device` (CUDA launches, Metal encoder
arguments, zero-copy Arrow views) and `oxidelake-storage` (io_uring submission)
carries a `// SAFETY:` comment whose invariant holds; every raw resource is
owned by an RAII type. Kernel sources bounds-check every global access;
`oxidelake-core` is `#![forbid(unsafe_code)]`. The plan codec validates magic,
version, column indices, types and dimensions before constructing a node.

## Performance findings

| ID | Impact | Where | Finding | Status |
|---|---|---|---|---|
| P1 | high | join operator / CPU kernel / CUDA ops | The build side was re-hashed (CPU), re-uploaded and its table rebuilt (CUDA) for **every probe batch**: O(probe batches × build rows). | **Fixed** — `JoinBuild` hashes once into a flat `JoinTable`; the device build is uploaded once per operator. CUDA still rebuilds its device table per batch from the resident columns (cheap relative to the upload; follow-up below). |
| P2 | high | `columns.rs` / operator layer | Eligibility was all-or-nothing per batch: one `Utf8` column sent the whole batch to the CPU path — the dominant real-world shape, and the reason the Metal conformance run had silently exercised only the fallback. | **Fixed** — only needed columns are uploaded; ineligible projected columns are gathered on the host at the device-compacted row ids. The conformance suite now asserts device execution via transfer counters. |
| P3 | high | `metal.rs` | One command buffer + `waitUntilCompleted` per kernel (6+ per filter batch) and a compute pipeline state created per dispatch. | **Fixed** — pipeline cache; one command buffer per phase (two waits per filter batch); the argument dummy buffer hoisted. |
| P5 | medium-high | `columns.rs`, `metal.rs`, `cuda/mod.rs` | Four copies per column round trip (extract `to_vec`, copy into the Metal buffer, download `to_vec`, clone in rebuild) plus a bit-by-bit validity repack. | **Fixed** — `Buffer` slices on extract, byte-aligned bitmap reuse, by-value rebuild, zero-copy Metal download through `Buffer::from_custom_allocation`. One host→shared memcpy remains (Arrow allocations are not page-aligned). |
| P7 | medium | operator layer | Inputs were uploaded before a backend could answer `Unsupported` (Metal joins/aggregates, Float64 predicates). | **Fixed** — `GpuBackend::supports_*` hooks consulted first. |
| P8 | medium | join | Every column of both sides was gathered, then most projected away. | **Fixed** — projection pushed into the probe (CPU) and the device sub-batch. |
| P9 | medium | sessions | 8192-row batches made GPU operators pay their fixed dispatch cost 122× per million rows. | **Fixed** — `GPU_BATCH_SIZE = 65 536` for GPU-targeted sessions. |
| P10 | medium | exec plumbing | Per-`execute()` telemetry registration and queue creation. | **Fixed** (see S2, S4). |
| P11 | medium | `datagen.rs` | Whole-table materialisation, one `String` per row. | **Fixed** (see S3); `s` built from 13 static strings. |
| P6 | medium | CUDA path | Every launch resolved its function through a mutex + `cuModuleGetFunction`. | **Partially fixed** — `CudaFunction`s cached per entry point. Pipelining two batches deep and pinned staging for downloads remain follow-ups. |
| P15 | low | `Cargo.toml` | Release binaries were stripped, so nothing could be profiled. | **Fixed** — `profile.profiling` (release + symbols). |

### Deferred, with plans

- **P4 — aggregate materialises the whole input** (`concat_batches`, then one
  single-threaded pass). Plan: fold `SUM/COUNT/MIN/MAX` per batch into typed
  accumulators keyed by group (they are decomposable), merge at the end, keep
  the "sorted, NULL group last" output. On CUDA, size the group table by
  distinct keys rather than rows and initialise sentinels on the device.
- **P12 — io_uring store is strictly slower than `LocalFileSystem`** (one SQE
  in flight, `get_ranges` serialised, `open()` per read). Plan: drain the job
  channel, submit one SQE per range with `user_data` = job slot, reap all
  completions, add `Job::ReadMany`, cache open descriptors. Linux-only — must be
  developed and measured on Linux (CI runs the conformance suite there).
- **P13 — spill manager** holds its lock across disk IO and scans O(n) for the
  coldest entry. Plan: per-tier `BTreeMap<(last_touch, id)>`, two-phase
  eviction (mark under the lock, IO outside), zero-copy IPC decode via
  `FileDecoder` over `Buffer::from(bytes)`.
- **P6 (rest)** — double-buffered H2D/kernel/D2H overlap as the spec describes:
  issue batch *i+1* before waiting on batch *i* (Metal `addCompletedHandler` /
  CUDA host callbacks bridged to `oneshot`).
- **P1 (rest)** — a `prepare_join_build` step on `GpuBackend` so CUDA keeps its
  populated hash table across probe batches, not just the uploaded columns.
- **P14** — rayon fan-out on tiny vector batches; Metal gather copies byte by
  byte where CUDA moves 8/4-byte words.

## Verification of this audit's changes

- `make gate` green on macOS (fmt, clippy on default/cuda/metal, 108 tests, docs,
  coherence, `cargo deny`); the Linux gate and io_uring lane run in CI.
- Metal lane: 49 tests; the on-device conformance suite passes **and** asserts
  `bytes_h2d > 0 && bytes_d2h > 0` for an Int64 filter over a batch with a
  `Utf8` column (the string column gathered on the host).
- New unit tests: `JoinTable` build/probe, sub-batch cutting and predicate
  remapping, telemetry transfer counters on the CPU backend, zero-copy
  extraction aliasing.
- CUDA changes (kernel spin-wait, function cache) compile and lint under
  `--features cuda`; they have **not executed** — recorded in `STATUS.md`.
